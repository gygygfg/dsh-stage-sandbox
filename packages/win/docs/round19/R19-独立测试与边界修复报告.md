## 3. 如实残余（未修 / 不声称）

> 以下 R16–R20 已同步进 `docs/Windows功能开启清单.md` §13 与 `tests/residual-baseline.ts`
> （R1–R20，`--plant` 变异自证），并由 `tests/r19-file-boundaries.ts` 的静态守卫钉住
> "不得悄悄启用/悄悄消失"。

1. **ntdll `Nt*/Zw*` 注册表写直调（P0，结构性）**：TS 档（默认车道）直写真实 hive、WAL 无记录；
   T1 档被令牌拒（真实 hive 不变）但无归因。治本需把 ntdll 写类加入 `WS_TARGET` + 线程级 re-entrancy
   guard + 载体矩阵验证；**raw `syscall` 指令不可能被任何 IAT 钩子拦住**，这是 TS 车道的结构性上限。
   影响面：需 AI 亲自执行原生 ntdll 调用才可利用（普通 .NET/reg.exe/pwsh 走 advapi32，已覆盖）。
   生产 green 复跑中 C1–C3 仍红（`NtCreateKey/NtDeleteKey/NtRenameKey` 真实 hive 被改、WAL 无记录）。
2. **`RegCopyTree/RegRenameKey` 生产 lane 复验"未验证"（P2，非产品红）**：复验探针可执行文件过期
   （更新源码后未重编，实际输出 `unknown mode`），本会话 zig 编译被环境阻断 ⇒ 该两条的 API 调用与 WAL
   未能取证。代码侧已加入 `WS_TARGET` 并实现 HARD_DENY+WAL（构建 0 warnings），下轮重编探针补验即可。
3. **`CopyFileExW/A` + `CopyFile2` hook（本轮新增，未完整验证）**：已消除"robocopy 直写真实盘"
   （实测真实盘不再被写，fail-closed），但**暂存语义未验证**；Lead 独立探针显示 direct-injector 下
   `cmd copy`/`xcopy`/`robocopy` 修前修后同样失败（node `fs.copyFileSync` 正常进暂存）⇒ 不作为已修功能声称。
   决策：**保留 hook（安全优先，真实盘零写），明确标注 fail-closed/未验证**，不声称"复制已可暂存"。
3. **硬链接遮蔽绕过（P1）**：`mklink /H <普通名> <.npmrc>` 后按普通名读回明文——路径黑名单无法识别同一
   数据对象的另一个名字；修复需 link-count 启发式（会误伤 WinSxS），建议由 T0/AppContainer 读面关闭。
4. **目录枚举元数据泄漏（P2）**：`Get-ChildItem`/`dir` 仍列出被遮文件名/大小/时间（无内容）；
   `FindFirstFile*/NtQueryDirectoryFile` 未 hook。
5. **工具面 `ctx.fs` 的 `readPolicy` 默认 `record`（只记不拦）**：敏感文件经 read 工具仍返回明文
   （R1 登记项/产品决策）。`block` 档对 readText/readBytes/readByteRange/listDir/stat/lstat 的守卫已代码核对，
   但**未做双档 e2e**。本轮**不改语义**：改成默认 block 会把大量正常运维读（项目 `.npmrc` 等）一并封死。
6. **纯托管 `.NET Framework` exe 注入即崩（P1，预存 carrier 缺陷）**：csc 编译的 exe 注入后
   `remote LoadLibraryW failed / 1114`（子进程 ucrtbase `0xC0000005`）；`WINSTAGE_SHIM_DISABLE=1` 对照正常；
   canonical/R18 私有 DLL 同样复现 ⇒ 非本轮引入。影响：.NET 证据只能走 powershell.exe（native host）。
7. **T1 档未 hook 写 API 的"无归因 fail-closed"（P1）**：令牌拒绝但无"沙箱拒绝"审计记录。
8. 其余既有口径（R18 已登记）：`file-cow-dispositions` 的 c6ps/c6ps-canary/c9 为 DSH-as-node 载体口径
   （plain-node 19/19）；沙箱 audit 的 `read-security-evtx` 因 OS ACL 不可归因按纪律记 fail；
   生产 `%TEMP%` lane 已复验（R18 未验证项，本轮 shell-runner 实测 TS/shim 8/8、真实工作区未被写）。

## 6. 结论与建议

- 四条重点线都有**真实红→绿**证据：遮蔽的读边界（A1/A2/A5）、危险命令分类（B1–B5）、
  注册表暂存（C1 生产 TS 车道实证）、关态零影响（D1–D3）。
- 下轮最高优先级（按风险）：
  1. **ntdll 注册表写 hook**（C2，P0 结构性残余；需 re-entrancy guard + 载体矩阵）；
  2. **CopyFileEx/2 暂存语义补验**（当前 fail-closed，普通 copy 在该载具下本就失败，需与载体矩阵一起验）；
  3. 托管 exe 注入崩溃根因（carrier 线）；
  4. 文件侧边界矩阵（ADS 已完成；硬链接/junction 穿透/大小写 rename/CAS/回滚/并发 apply 仍未做独立审计）。
- **不声称**："TS 档已是硬边界"。它仍是 **IAT 钩子 + 暂存**的用户态边界；硬边界只能靠 T1 受限令牌
  或 T0/AppContainer（读面）兜底；这一条已与全部读数一起如实记录。
