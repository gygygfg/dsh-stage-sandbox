## 0. 结论速览

1. **NeoAI 在 2026-10-22 完成了一次设计转向**：删除了全部“按命令文本硬拒绝”的逃生口
   （`risk.deny_reason` / `text_guard` / `DENY_BINS`），并把
   **「安全边界只能由内核/运行时提供」**确立为第 6 条核心不变量。文本匹配从此**只能**
   提升风险等级或要求人工复核，**不得**作为放行/拒绝的根据。
   （提交：`d4c88bb0` → `53fb7ca7` → `fc93b344` → `a75fe91e` → `98f8069c` → `52c8de4f`）
2. **本仓旧差距输入（2026-09-30）的核心建议已失效**：它建议 Windows 侧补“不可被确认覆盖的
   硬拒绝清单”（按命令名），而 NeoAI 现在恰恰把同类机制**整段删除**了。照旧清单补，
   等于把 NeoAI 刚证伪的设计再实现一遍。
3. **本仓当前仍有一处“文本判定即边界”的实现**（P0）：暂存写自检未通过时，
   `assertStagingWriteEnforceable()` 只要 `classifyCommandRisk()` 判“只读”就放行
   （`src/executor.ts`）。TS 档（纯用户态 IAT shim）与“未初始化”档都没有内核写屏障，
   一旦文本漏判，命令会真实执行且不暂存。
4. **本轮（R44）已修**：把只读豁免改为**结构性写屏障判定**——
   只有受限令牌（T1/T1S）或 AppContainer（T0）在场时才允许文本只读命令继续；
   TS / 无屏障一律 `STAGING_WRITE_UNVERIFIED_NO_BARRIER` fail-closed。
   同时把 `writeBarrier`（kernel / user-mode / none）写进闸门决策、`initReport`、
   `run()` 结果与 `sandbox-lane.json`，让用户能直接看到“此刻的边界由谁提供”。
   `[实测]` 新增 41 条断言（R44）+ 34 条断言（R45）全绿；全量关口见 §5。
5. **默认 lane 的诚实性问题仍在**（P0-1，未在本轮改默认值）：DSH 插件默认 `tier='auto'`，
   探测通过即走 TS（用户态边界）。**R45 已提供显式内核边界入口 `tier:'T1S'`**（受限令牌 +
   shim，shim 缺件即 fail-closed），并把 TS 的“用户态边界”写进状态结论；但默认值仍是
   auto⇒TS，是否把“默认必须内核边界”作为产品策略，需单独决策。
6. 其余差距（P1/P2）：网络强制生产不可达、读面仍黑名单且默认只记录、无假凭据/出站守卫、
   无脚本正文扫描、L0–L3 策略未接生产审批、输出上限仅事后截断、命名管道无 mask、
   无 grants/replay、无 UI/IPC/COM/服务/WMI 面、无 ETW/minifilter。

## 1. NeoAI 当前设计（2026-10-22）

### 1.1 六条核心不变量（`docs/sandbox.md` §1，逐字要点）

1. dry-run 不构成安全边界；预测与真实执行都在受控运行时中。
2. 隔离执行只改可丢弃的私有状态，不写宿主真实工作区、不调真实外部写接口。
3. commit 只发布已冻结、已校验、已授权的候选，不重跑原命令。
4. 硬拒绝不可被人工确认覆盖；未知结果不报告为成功或可重试。
5. 沙箱服务缺失且 `fail_closed=true` 时拒绝执行；防御层缺失按“预防性 / 补救型 / 仅告警”
   三层语义降级，且绝不静默。无隔离后端 ⇒ 禁用沙箱、退回**同步事前审批**，
   不再提供 `allow_unisolated` 直跑逃生口。
6. **安全边界只能由内核/运行时强制提供**：seccomp、capability、命名空间、设备隔离、
   cgroup、网络门禁、人工审批；字符串/正则/命令名黑名单**不得作为拒绝依据**。
   文本匹配只允许用于风险分级与提示文案，命中最多导致强制人工复核。

### 1.2 删除文本硬拒后的替代机制（这是最值得对标的部分）

| 原文本黑名单想拦的 | NeoAI 现在的真实拦截 | 层级 |
|---|---|---|
| `modprobe/insmod/reboot/kexec/bpf/perf/swapon/sysctl` | seccomp 拦对应 syscall；`/proc/sys` 只读 | 内核（预防） |
| `iptables/nft` | 缺 `CAP_NET_ADMIN` ⇒ `EPERM`（busybox 软链绕不过） | 内核（capability） |
| `mkfs/dd of=/dev/*` | seccomp 拦 `mknod/mknodat` 设备位 + 设备门禁 | 内核 + 用户态 |
| `curl \| sh` / `eval "$(curl …)"` | 新增 `exec_guard` 按真实 `execve` 链归因 → `cgroup.kill` | 内核观测 + 补救（副作用可能已发生一次） |
| “危险命令”但其实只读（`kmod --help` / `grep 'curl x \| sh'`） | 不再拒绝，最多 `needs_confirm` | advisory |
| 完全没有强制层的机器 | `effective_approval_mode()` 强制 `prompt`（同步事前审批），禁用 async | 人 |

### 1.3 其他可迁移设计思想

- **CI 门禁化**：`scripts/ci_invariants.sh` 用 grep 判定“不得重建文本硬拒表/API”，
  并做过反向验证（注入违规必须红）。设计准则不是评审者的记忆。
- **未知是一等状态**：`OUTCOME_UNKNOWN / RECONCILING / RECOVERY_REQUIRED / ROLLBACK_FAILED`
  显式建模，不报成功、不自动重试。
- **三层语义分级**：每层写清“预防性 / 补救型 / 无强制层”，降级时写 evidence + 事件 + 提示。
- **同意粒度**：`host:port@<exe>`，进程变化即失效；headless 直接 deny；等待人类的时间不计超时。
- **grant 是可消费预算**：scope/operations/budget/TTL/revoked/usage，Agent 只能请求匹配。
- **裁决可回放**：evidence 落 `{facts, verdict, policy_version}`；规则变了如实报 `version_mismatch`。
- **残余边界清单 + 基线断言**：把“已知残余”写成测试期望，变化即报警。

## 4. 本轮完善（R44）：只读豁免从“文本判定”改为“内核写屏障判定”

### 4.1 设计

新增纯函数（`src/executor.ts`）：

```text
writeBarrierFor(launchMode):
  'restricted-token' | 'shim+restricted-token' → 'kernel-restricted-token'
  'appcontainer'                               → 'kernel-appcontainer'
  'shim'                                       → 'user-mode-shim'   // 不是边界
  其它/未初始化                                 → 'none'
```

`assertStagingWriteEnforceable()` 的判定改为：

1. `verdict === 'pass'` ⇒ 放行（与屏障无关）；
2. `verdict !== 'pass'` + 文本只读 + **内核屏障** ⇒ 放行，动作
   `allowed-kernel-write-barrier`，并标 `readOnlyAdvisoryOnly:true`（文本只是提示）；
3. `verdict !== 'pass'` + 文本只读 + **用户态/无屏障** ⇒ 拒绝
   `STAGING_WRITE_UNVERIFIED_NO_BARRIER`（不再有“文本放行”这条路径）；
4. `verdict !== 'pass'` + 有写/判不出来 ⇒ 仍按原文拒绝（fail-closed 方向不变）。

### 4.2 可见性

- 闸门决策（`stagingWriteGate.lastDecision/trips`）新增 `writeBarrier`、
  `readOnlyAdvisoryOnly`；
- `initReport` 与 `run()` 结果新增 `writeBarrier`；
- DSH 侧 `sandbox-lane.json` 新增 `writeBarrier`（`summarizeLane()` 同样透出），
  用户可通过 `/winstage status` 直接回答“现在的边界是内核还是用户态”。

### 4.3 测试（`tests/r44-write-barrier.ts`，41 断言）

- 屏障分类真值表（T1/T1S/T0/TS/未知）；
- T1/T1S/T0 + 文本只读 ⇒ 放行且动作/字段正确；
- TS（shim）+ 文本只读 ⇒ 拒绝 `STAGING_WRITE_UNVERIFIED_NO_BARRIER`，错误带
  `writeBarrier/launchMode`，命令未执行；
- 未初始化 + 文本只读 ⇒ 同样拒绝；
- T1 + 写类/判不出来 ⇒ 仍拒绝；
- `verdict=pass` ⇒ 与屏障无关地放行；
- `summarizeLane()` 与 `shell-executor` 落盘字段检查；
- 源码不变量：`allowed-read-only-bypass` 不得复活、
  `isKernelWriteBarrier()` 必须在放行分支、变异体检查证明判据非空洞。

### 4.4 未改的东西（如实声明）

- **没有改默认档位**：`tier='auto'` ⇒ TS 的默认链路保持不变。把默认改为 T1S 会改变所有
  用户的日常执行链路（性能/兼容性/装配失败面），需要单独决策；本轮只把“当前边界是谁”
  变成可机读、可展示的事实。
- **没有引入新的“文本硬拒绝”**：拒绝仍只发生在“暂存不可信 + 无内核屏障”这一结构性
  条件下；文本只影响“是否继续使用已有的内核屏障”，不创造新边界。

### 4.5 R45：显式内核边界档（`tier='T1S'`）+ 状态诚实性

R44 之后仍有一个问题：用户知道 TS 只是用户态钩子时，没有一个**简单的显式入口**要求
“内核边界 + 暂存/WAL”；T1S 只能靠 `WINSTAGE_T1_SHIM=1` + `tier:'T1'` 组合进入。而且
状态面板把 T1S 误报成“未生效/已降级”。

本轮改动：

- `tier:'T1S'` 成为显式入口：`transparencyProbeNeeded()` 统一探测条件（TS/auto/T1S），
  `planT1ShimMode()` 新增显式 T1S 分支；shim 不可用/未探测 ⇒ `T1S_UNAVAILABLE`
  fail-closed，**绝不静默降回 T1**。T1S = 受限令牌（内核写屏障）+ shim（暂存 + WAL 归因）。
- 修复状态误报：`summarizeLane()` 之前只把 `launchMode==='shim'` 判为 active，T1S
  （`shim+restricted-token`）落到 degraded 分支；lane 产物的
  `degraded: effectiveLane !== 'shim'` 也把 T1S 算成降级。现在 T1S 报 active +
  `writeBarrier=kernel-restricted-token`。
- TS 的结论明确写出：“写边界=用户态 IAT 钩子（**不是内核边界**）；raw syscall /
  未 hook 面不受约束；需要内核写屏障请用 `tier:'T1S'` 或 `'T0'`。”
- 测试：`tests/r45-kernel-lane.ts`（34 断言，含探测条件/显式 T1S/fail-closed/状态文案/
  源码接线检查）。

**仍未改**：默认仍是 `auto` ⇒ TS。R45 提供的是“可显式要求内核边界”的入口，不是默认策略
变更；默认是否改为 T1S 仍需单独决策（见 §6 P0-1）。

### 4.6 R46：已保存撤销（对标 NeoAI review 的 undo 快照；文件面）

R44/R45 之后，用户面仍缺 NeoAI 的一条能力：**已保存的改动可撤销**。本仓面板文案此前逐字
写 “cannot be undone”，`applyCandidate` 成功后立即删除 `apply.journal`，误点批准只能手工
恢复且原内容已被真实盘覆盖。

本轮改动（`src/workspace.ts` + `/winstage undo`）：

- apply 成功且确有真实写入（且非回滚失败）⇒ 把本批实际写入的回滚快照持久化到
  `<store>/undo/<id>.json`（sha256 checksum，受同一 64 MiB 快照预算约束）。
  记录写失败**不**回滚已成功的 apply，只报 `undo.available=false` + 原因。
- `/winstage undo [--list] [id]`：撤销前做**整批并发预检**——任一文件在保存后被外部改过
  ⇒ `conflict` + `nothingWritten:true`（零写，绝不覆盖）；成功后记录归档到
  `undo/undone/`，不再出现在 `--list` 里。
- 覆盖修改 / 新建（含新建父目录回收）/ 删除（内容 + 权限位恢复）；幂等
  （已回状态 ⇒ `already-undone`）；记录损坏 ⇒ `corrupt` 且拒绝覆盖；跨会话 ⇒
  `session-mismatch`。
- **边界（如实声明）**：只覆盖**文件面**；注册表候选不在这条链上（命令文案与文档明写）。

测试：`tests/r46-undo.ts`（31 断言）。

## 6. 仍存差距（未在本轮修，按优先级）

### P0-1 默认 lane = TS（用户态边界）

`dsh-plugin/shell-executor.ts` 的 tier 默认 `'auto'`；`selectLaunchMode()` 在探针通过时
选 `shim`。shim 是 IAT 钩子，raw syscall / 未 hook 模块可绕过（`ws_hook.c` 自述）。
**R45 已提供显式内核边界入口**（`tier:'T1S'`，fail-closed；状态面板把 T1S 报 active、
把 TS 的“用户态边界”写进结论），但**默认策略**仍需决策：

- 选项 A：默认 T1S（受限令牌 + shim），代价是装配失败面与性能；
- 选项 B：保持 auto，但在 `writeBarrier` 为 `user-mode-shim` 时在面板/状态行明示
  “当前写边界是用户态”（R45 已在 `/winstage status` 结论与 `sandbox-lane.json` 做到）；
- 选项 C：提供配置项 `requireKernelWriteBarrier`（默认 false，显式开启则 auto 不走 TS）。

### P1

1. **网络生产不可达**：插件不传 WFP bindings/GUID/pin ⇒ OFFLINE 只能拒绝执行；
   且无 localhost / DNS / 端口归属 / 云元数据策略。
2. **读面**：29 条黑名单 + 默认 record；无 allowlist；T0 非默认。
3. **凭据**：无假凭据注入、无出站守卫、无流账本。
4. **脚本正文扫描**：`-File`/`-EncodedCommand` 不读脚本正文。
5. **L0–L3 / 策略引擎未接生产审批**：`plugin/*` 已写但 `apply()` 委托 host-plugin。
6. **输出上限**：捕获无界，截断在收集之后。
7. **命名管道/ALPC**：无名称级 mask（`docker_engine`/`lsass`/SCM 等）。

### P2

grant / policy replay、UI/桌面/IPC/COM/WMI/服务/计划任务、ETW/minifilter、
输出/暂停的 cgroup 等价物、未知状态一等建模、conceal 反指纹。

**测试环境（本机当前）**：Smart App Control 处于强制态（`VerifiedAndReputablePolicyState=1`），
运行时新写入的无签名探针 exe 被 OS 拒绝（Win32 4551）。8 个依赖“现场编译探针/注入器”的套件（7 个在 verify 内 + 1 个沙箱段 `registry-unstaged-wow64`）
现在**显式 SKIP**（`tests/_app-control.ts` 只读探测注册表；`RESULT: SKIP …`，退出码 0），
不是伪造 PASS，也不是把红留在关口里；SAC 关闭/未强制的机器上自动恢复完整运行。
其余 53 个套件真实运行并通过。若要在这台机器上跑满全部 61 个套件：关闭 SAC，或对测试产物做
受控签名 / 应用控制策略豁免（管理员）。证据与判定细节见 §5。
