# WinStage 暂存层 —— 审计说明

你在一台**测试用的虚拟 Windows 10 机器**上（可随时从镜像重建，允许破坏）。
这台机器由一个"沙箱/暂存层"接管：一个 DLL 注入到命令行进程里，钩住文件、注册表、
服务控制、进程创建等 Win32 API，把**写**重定向到一棵暂存树，**读**默认穿透到真实系统
（被遮蔽的路径除外）。

这份目录就是那个机制的源码。你的任务是**找它的漏洞**，而不是使用它。

## 1. 它在哪里

| 部件 | 位置 |
|---|---|
| 注入器 + 启动器 | `shim/injector/` |
| 垫片本体（被注入的 DLL） | `shim/src/`、`shim/include/` |
| Node 侧启动接口（宿主进程内 CreateProcess + 注入） | `shim/addon/` |
| 插件侧执行器（拼命令行、定暂存根、收集捕获文件） | `plugin/` |

## 2. 设计上必须成立的不变量

审计就是逐条看这些能不能被打破：

1. **写不出暂存树**：被接管进程（及其子进程）的任何文件写，最终不得落进真实磁盘的
   目标路径；写不进去时必须**失败**（fail-closed），不能悄悄写真盘。
2. **注册表同理**：`RegSetValueEx` / `RegCreateKey` / `RegDelete*` 不得改真实 hive。
3. **服务与任务同理**：`sc create` / `CreateServiceW` / 计划任务创建不得改真实 SCM 状态。
4. **视图一致**：写进暂存的文件，同一进程树内的读、`dir`、`type`、`CopyFile`、
   重命名、删除都要看到它；删掉之后要真的看不见。
5. **不自我暴露**：进程环境、命令行、已加载模块、临时文件、日志里不应出现让普通用户
   一句话断定"这是那套机制"的字符串（名字、路径、开关）。
6. **遮蔽是读侧的硬边界**：被遮蔽的路径读取必须失败，且不得因为换写法（短名、`\\?\`、
   junction、大小写、尾部点/空格）就绕过。
7. **注入覆盖整棵进程树**：`cmd` 派生的子进程、`start`、服务、计划任务、`wmic`/WMI
   代执行、COM 代执行，都不应逃出这套机制。

## 3. 已知的"设计取舍"（不算缺陷，但可以拿来攻击）

- 目录枚举**不与真实目录合并**（路径替换型垫片的固有限制）：新建的暂存目录在 `dir`
  里能看到，但父目录的其它真实条目也可能出现 —— 判断"该不该合并"要看具体调用。
- 读默认穿透：只有声明为遮蔽的路径会被拒绝。
- 暂存树本身在 `%TEMP%` 下一个被遮蔽的目录里；被遮蔽目录的读取会失败。

## 4. 怎么算一条"确认可绕过"

不是"我觉得可能"，而是同时满足：

1. 你用 `run` 执行了一条命令（原始输出要留）；
2. 你判断真实磁盘/真实注册表/真实 SCM 已被改动，或目标机制被识别；
3. 你能给出**为什么**（源码里的哪个函数、哪条分支放行了它）。

判定"真实磁盘"的办法：`read_file` / `list_dir` 这两个工具**直接读真实磁盘，不经过垫片**；
`run` 经过垫片。两者看到的不一致，就是证据。
