## 2. P0 修复详情（本轮最大成果）

### 2.1 缺陷（golden 下 Lead 实测）

沙箱内以**绝对真实路径**创建 `A\sub`、`A\a.txt`、`A\sub\b.txt`、`root-new.txt` 后：属性面/直读正常，
但 `Get-ChildItem`/`[IO.Directory]::GetFiles`/`GetFileSystemEntries`/`cmd dir` 全部看不到；
`ws` 根目录只列真实种子；递归删除失败。
源码事实：`shim/src/ws_hook.c` 的 `g_targets[]` 只有 `GetFileAttributes*`，**没有任何 `FindFirstFile*`/`NtQueryDirectoryFile`**。

### 2.2 修复实现（`shim/src/ws_dirfind.c`，新文件）

* 在 **Win32 `Find*` 族**做合并：`FindFirstFileW/A`、`FindFirstFileExW/A`、`FindNextFileW/A`、`FindClose`。
* real 侧用 captured original 枚举；staged 侧枚举 `<stageRoot>\fs\<盘符去冒号>`；
  大小写不敏感去重、**staged 覆盖 real**、**whiteout 项丢弃**、按 pattern 过滤。
* 合成句柄表承载"待发条目"，未知句柄**原样透传**；字面名（无通配符）不合并直接交原函数（避免为 `ws_ensure_dirs` 造出的幻影父链编造结果）。
* `ws_hook.c` 加 4 个 target 与捕获表；`winstage_internal.h` 加声明；`ws_file.c` 的 `ws_should_intercept` 去 `static` 共享路径判据。

### 2.3 修复过程中挖出的两条深层根因（都值得记住）

1. **hook `ntdll!NtQueryDirectoryFile` 不够**：它装得上（`iatSites=3 original=yes`）却**从不被进入**
   （整轮 run `R12-DIR-ENTRY` 计数 0），而 `kernel32.dll`/`kernelbase.dll` 都确实 import 它 ⇒ Win32 `FindFirstFile*` 路径不经该槽。
2. **"新 DLL ⇒ TS 档退化成 T1"的真因**（曾把两名修复者都挡在门外）：
   `<out>/stage-root/sandbox-lane.json` 的 `fallbackClass=carrier-init-failed`，
   `injectorOk=true childExit=0xFFFF0000 ... "Version v4.0.30319 of the .NET Framework is not installed..."`。
   根因是两个代码缺陷让**合并视图恒为空**：
   * `HeapReAlloc(NULL, …)` 被当 `malloc` 用（返回 NULL ⇒ entries 恒 0 ⇒ PowerShell 把 `Framework64` 枚举成空目录 ⇒ 载体 CLR 判"没有 .NET" ⇒ 退出 `0xFFFF0000`）；
   * 重入护栏用了**进程级**变量，一旦留在置位状态，所有枚举静默直通真实盘。
   分别改成 `ws_ent_grow()`（NULL→HeapAlloc）与 `_Thread_local` 后恢复。
   > 这正是"暂存面在工作 ≠ 沙箱按 TS 档在工作"的又一实例：**必须逐 run 看 raw lane**。

**D1 的定位过程（Lead 追加探针 `.t\r12\accept/prompt-d1probe.txt`，读数 `.t\r12\accept3/out/`）**：

```
P1 GetChildItem A（非递归）      OK => sub,a.txt
P2 GetChildItem A -Recurse      THREW Win32Exception: The system cannot find the path specified
P3 GetChildItem ws -Recurse -Depth 1  THREW Win32Exception: The system cannot find the file specified
P4 GetChildItem ws -Recurse     THREW 同上
P5 Get-Item A                   OK => DirectoryInfo
P6 [IO.Directory]::GetDirectories("ws")                 OK
P7 [IO.Directory]::EnumerateFileSystemEntries(AllDirectories)  OK => 5
P8 DirectoryInfo.EnumerateFileSystemInfos(AllDirectories)      OK => 5
P9 DirectoryInfo.GetDirectories('*',AllDirectories)            OK => A,sub
P10 cmd dir /b /s               OK（5 项）
P11 Resolve-Path A / P12 Test-Path A\sub\b.txt   OK / True
```

⇒ **只有 PowerShell 提供程序的递归面抛错**；同一棵树上 .NET 的四种枚举、`cmd dir /s`、单层 `Get-ChildItem` 全部正常。
`shim.log` 里能看到 `R12-DIR build … ws … entries=2` 连续两次成功，**之后失败的调用根本没有进入我们的钩子**
（既没有 `R12-DIR build` 也没有 `ATTRDBG`）⇒ 失败点在"枚举完成之后、PS 提供程序下一步调用的那个 Win32 API 上"。
本轮试过一个假设（字面名无通配符时一律透传 ⇒ overlay-only 路径从 `FindFirst*` 面报 NOT_FOUND），
已把该分支改成"真实路径存在才透传、否则由 staged 侧合成单条"，**但 D1 仍然复现** ⇒ 该假设不是 D1 的成因（改动本身保留，因为它让字面名查询与属性面口径一致）。
**下一步建议**：在 `FindFirstFileW/ExW`、`GetFileInformationByHandle`、`NtQueryInformationFile` 三个钩子里加"未命中日志"
（例如统一打 `R12-CALLMISS api=… path=… err=…`），再跑一次 `Get-ChildItem -Recurse`，看最后一个未命中的 API 是什么。

* 但修复者自述"沙箱内本轮管道返回 `ENOENT` 而非 `ENOTCONN`，原崩未复现 ⇒ 不声称修好"。

### 5.2 `tests/shim-artifact-integrity.mjs` 断言写错（本轮修正）
`无 stale 可恢复时，恢复被明确拒绝而不是静默成功` 这条断言在**镜像本来就健康**时调用 `repairFromStale()`：
三个产物"已存在且形态正确"⇒ 全部进 `skipped` ⇒ 工具按契约返回 `ok:true`（含义是"本来就健康"），
而断言要求 `ok===false` ⇒ 恒假。此前之所以是绿的，只是因为那时 `shim/out` 里恰好存在 `.stale-*` 副本、走了另一个分支
（`shim/out/` 是 git-ignored 的临时产物目录，`tests/` 与它无关）。
**修正**：先在镜像里制造一个**待修产物**（删除 injector）再调用，断言"明确拒绝且列入 unrecoverable"——
这才是该分支想测的东西。修正后该套件 **57/57 PASS**。
