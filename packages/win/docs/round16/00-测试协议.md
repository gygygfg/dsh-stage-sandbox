## 0. 硬约束（违反即任务失败）

1. **本线程（你所在的 3080 web 会话）不许加载 WinStage 沙箱**：不许在本会话里启用插件、不许改
   `%DSH_HOME%\profiles\web\**`、不许跑 `dsh plugin --profile web ...`。沙箱只能在**新起的独立进程**里加载。
2. **不改本线程工具/profile**：只允许读 `%DSH_HOME%\profiles\web\**`；只允许**新建** `profiles\sbx\`（已存在，勿动）。
3. **不 spawn 新 teammate**。要并行就用 pwsh 后台 job 同时发多个 `sbx-thread.cmd`。
4. **不改仓库源码**（`src/**`、`dsh-plugin/**`、`tests/**`、`tools/**`、`shim/**`）：发现缺陷**只报告**，
   由 Lead 统一修复。若你确信必须改，先 `send_message` 给 `lead` 说明理由，得到同意再动。
5. **不碰** `%LOCALAPPDATA%\Temp\winstage-stage\dsh-host`（那是 3080 宿主的暂存根）、不 kill 3080 宿主。
6. **证据里不得出现密钥明文**：只记 sha256 / 长度 / 首尾 4 字符。若测试过程中产生了敏感文件副本，
   **必须删除**并在报告里记下 sha256（见 §5）。

## 1. 怎么"新开一个 DSH 沙箱线程"（唯一入口）

```cmd
cmd /c "<REPO>\docs\archive\round10\env\scripts\sbx-thread.cmd" <wsDir> <promptFile> <outDir> winstage
```

- `<REPO>` = `C:\Users\Administrator\Desktop\dsh-winstage-sandbox`
- 脚本自动做对的事：`WINSTAGE_SHELL=1`、清 `DSH_SESSION_ID`、**钉唯一** `WINSTAGE_STAGE_ROOT`、
  跑 `dsh --profile sbx --json -`（任务文本从 promptFile 走 stdin），最后跑 `sbx-extract.mjs` 抽证据。
- 每个 run 必须有**独立**的 `<wsDir>`（`.t\r16\<你的域>\ws-*`）和 `<outDir>`（`.t\r16\<你的域>\run-*`）。
- 第 4 参 `platform` ⇒ `WINSTAGE_SHELL=0`（平台工具，**真实盘会被写**）——只作对照，用一次性目录。
- **并行**：同时发多个 `sbx-thread.cmd` 是支持的（每 run 钉唯一 stage root；R10 `evidence/parallel/` 已实测）。
  建议每个域最多 2 个并发，单域总 run 数 ≤ 6。
- 超时：单 run 可能 3–10 分钟，pwsh 调用给 `timeoutMs: 900000`，或用后台 job。
- **不要自己手拼 `dsh` 命令行**（`call dsh`、清环境变量、钉根这些坑很多）；脚本坏了就把原因写进缺陷并
  在 `.t\r16\<域>\` 下放你自己的 wrapper。

### 1.1 有效 run 的四条判据（缺一不可，必须写进报告）

| # | 判据 | 怎么读 |
|---|---|---|
| 1 | loader 无告警 | `<outDir>\stderr.txt` **0 字节** |
| 2 | 暂存面在工作 | `<outDir>\stage-root-inventory.txt` 含你让沙箱写的文件，且同 run 暂存根有 `candidates\*.json` |
| 3 | 真实工作区零污染 | `<outDir>\workspace-inventory.txt` 只有你**预放的种子**文件 |
| 4 | **lane 真的是 TS** | `<outDir>\lane.txt` 里 `LANE_OK=true`（= 同 run `sandbox-lane.json` 的 `degraded===false` **且** `tierEffective==='TS'`） |
| 5 | **隔离只能由宿主侧读数判**（R16 新增，来自独立复核者的方法论结论） | 任何"零落盘 / 零注册表改动"的声明，必须由**沙箱外的不受限进程**对真实盘/真实注册表取前后读数；**沙箱内的 `Test-Path` / 枚举 / 自报读数不得自证隔离** |

> ⚠ **判据 4 是致命判据，不是补充说明。** 前三条全绿也可能已经静默降级到 T1
> （R10 §5.7 实测：注入器缺失时暂存照样工作、真实盘照样干净，而 lane 是 `T1/degraded=true`）。
> **lane 不是 TS 的 run 一律标 `INVALID-LANE`**，不得用来声称"沙箱隔离生效"。
>
> ⚠ **判据 5 同样是致命判据（R16 新增，用真金白银换来的）。** R16 域 3 实测：一次 run 的
> **四条判据 4/4 全绿**（`LANE_OK=true` / TS / stderr 0B / 真实工作区只有种子 / candidates 在），
> 同时同 run 的 `msiexec /a` 经**进程外** `msiserver` 在真实盘写出 **2,449 文件 / 134.9 MB**，
> 且沙箱内 `Test-Path` 还会**假绿**。⇒ "暂存面在工作 + 档位是 TS" **推不出**"真实盘零改动"。
> 每个域必须给出**宿主侧**（不受限的 pwsh）真实盘/真实注册表前后对照；拿不到就写 `not-run`。

## 2. promptFile 怎么写（喂给沙箱线程的任务文本）

必须显式写清：

1. 具体动作（逐条命令 / 逐条路径，不要含糊）；
2. **`do not ask any questions`**（headless 没有审批应答者；`ask_user_question` 会挂）；
3. 让它把关键读数**写进你能读到的地方**：优先"在 workspace 里写 `<name>.txt`"（会进暂存树）
   并在最终回答里同时给一遍；
4. 不要依赖审批：`sbx` profile 已钉 `danger-full-access` + `approval: never`；
5. 沙箱线程里的 `write`/`edit` 工具产物**只进暂存树**（候选 `status: pending`，headless 永不提交）；
   `pwsh` 工具在 WinStage shell 里跑，写操作同样进暂存。

## 4. 已知背景（省得你重复踩）

- 沙箱引擎 = `shim/out/winstage-shim.dll` + `winstage-inject.exe` + `winstage-probe.exe`（golden 三件套）。
  R15 已把 R12–R14 的 shim 改动整体撤回，**golden 不含 P0 目录枚举修复** ⇒ `Get-ChildItem` 对 overlay
  新建目录、递归删除等行为可能"回到 R12 之前"（这是**已知**的，别当新缺陷报，但要复验读数）。
- 长路径阈值：逻辑 **158** 字符即触 260（stage 前缀约 90）——已知未修。
- 网络档位：`networkTier` 默认 `OBSERVED_ONLINE`，**本机不装真实 WFP 过滤器** ⇒ 网络强制**未落地**
  （lane 的 `network` 段写 `state: not-implemented`）。如实记录，不要当成"新发现"当成修复项。
- 敏感读：已知"写保护成立、读保密不成立"；写意图 open 的**明文 copy-up**（D6-1）在 golden 下依然存在
  ⇒ 测敏感域时**必须清理**产生的明文副本（§5）。
- 封印面文件（`src/*.mjs`、`tests/*.mjs`、`dsh-plugin/*.mjs`、`tools/*.mjs`、`autotest.mjs`、`run.cmd`、
  `testservice.cmd`、`verify.cmd`）改动后要 `node tools\baseline-sha256.mjs --write` 重封 —— 但**本轮你不改**。

## 5. 敏感材料清理规程（敏感域强制）

1. 测试前记录真实敏感文件的 sha256 + 字节数（**不要打印内容**）。
2. 测试后立刻扫描 `.t\r16\**` 与 `docs\round16\**` 是否出现敏感文件副本（按文件名 + 内容指纹），
   发现即删，并在报告里记：删除路径、sha256、字节数、产生原因。
3. 报告里**只允许**出现 sha256 / 长度 / 路径，禁止出现密钥或令牌原文。
