> 证据分层：`[实测]` = 真的跑出该结果。

## 一、项目规范

### 1.1 Cordis 插件规范（外壳必须遵守）

本插件是 **Cordis 插件**，装配由 `dsh-plugin/cordis.patch.yml` 驱动。规范要点：

| 项 | 规范 | 本仓现状 |
|---|---|---|
| 入口形态 | 函数插件 `(ctx, config)` / 类插件 `class extends Service` / `{ apply }` 对象 | `. → plugin/index.ts`（函数插件，导出 `name/inject/Config/apply`） |
| 配置 | `Config` 必须是**真** schema（满足 `Plugin.Base.Config: StandardSchemaV1`） | `plugin/config.ts` 用 `@deepseek-ai/schemastery`（**不再**手写伪造外观） |
| 服务注册 | 类插件 `super(ctx, name)` → `ctx.<name>`；服务名**单例** | `ctx.fs`（winstage-fs）、`ctx.shell`（winstage-shell）各自唯一提供方 |
| 依赖声明 | `static inject` / `export const inject` | 入口 `inject = []`；命令面用 `ctx.inject(['commands'], …)` 惰性注册 |
| 生命周期 | 用 `ctx.effect(fn, label)` 注册可回收副作用 | 命令注册、面板路由均走 `ctx.effect` |
| 开关语义 | 设置页开关 = **单一权威**；关 ⇒ 整体退回平台面 | `staging-fs` 现读 `config.enabled`；每覆盖层先查 `stagingEnabled()`，假则 `super.*` |

**两条硬纪律（历史事故换来的）**：
1. **同一服务名不能有两个提供方**。替换必须写成「禁用平台行 + 插入本插件行」；**不要**做行级热切换（提供方回收竞争会把宿主进程搞崩，`docs/DSH集成.md §4`）。
2. **`name` 在非 insert 补丁里是断言**：不匹配 ⇒ 整条补丁（含其 `config`）被**静默跳过**。故改名 bundle 行必须同步改所有 profile 覆盖层；profile 覆盖 `config` 是**整体替换**（未写的键静默消失）。

### 1.2 单一事实来源（SSOT）纪律

| 事实 | 唯一来源 | 守护 |
|---|---|---|
| 套件清单 | `src/testrunner.ts` 的 `OFFLINE_SUITES` | `tests/suite-wiring.ts` 机器比对 `verify.cmd` |
| 源码封印 | `docs/源码基线.sha256`（`sha256  <path>`） | `tests/baseline-integrity.ts` |
| shell 开关判定 | `dsh-plugin/assembly-toggle.ts` + YAML 内联（逐字一致） | `tests/assembly-toggle-selftest.ts` |
| 暂存根（两个"根"同源） | YAML 锚点 `&winstageRoot` | `shell-executor` 的 `effectiveWorkspaceRoot()` 交叉校验 |
| 敏感遮蔽清单 | `src/paths.ts` 的 `MASK_CLASSES` | `tests/paths-masks.ts` |

**禁止**为同一事实写第二份实现；若因 YAML/运行期限制必须重复，必须加**逐字等价断言**（见 assembly-toggle 的 A7/A8）。

### 1.3 未提供的保证必须点名

不声称做不到的隔离。例：NeoAI 的规则受限执行（`setfenv`+指令预算）在 JS 无等价物 ⇒ 本仓 `plugin/policy/engine.ts` 明确写"规则作者须为可信代码"，并在 `guaranteesNotProvided` 里点名。既有残余边界以 `R1–R12` 记在 `tests/residual-baseline.ts`（不得悄悄消失）。

### 1.4 证据分层与"能 FAIL 的断言"

- 一切结论标 `[实测] / [推断] / [未实测]`；`not-run` 不得写成"通过"。
- 每个判据必须**能 FAIL**（有负面对照/变异自证，如 `assembly-toggle-selftest` 的 C 段）。
- **一个永远不报失败的运行器比没有运行器更糟**（`tests/meta-runner.ts` 反证运行器本身）。

### 1.5 TypeScript 与工程约定

| 项 | 约定 |
|---|---|
| 模块 | ESM；`module: NodeNext`；**相对导入带 `.ts` 扩展**（`allowImportingTsExtensions`） |
| 运行 | 源码是 `.ts`，用 **tsx** 运行：`node --import tsx <file>.ts` |
| 严格度 | 全量迁移期 `strict:false`（过渡）；新写的 `plugin/**` 保持类型干净、**不加** `@ts-nocheck` |
| 机械转换标记 | 由 `.mjs` 机械转换而来的文件带首行 `// @ts-nocheck —— …过渡脚手架`，类型逐步补齐 |
| 依赖 | 平台包 `@deepseek-ai/*` 声明在 `devDependencies`（版本需与目标 harness 对齐） |

## 二、测试流程

### 2.1 三层结构

| 段 | 套件 | 需要未受限会话？ | 内容 |
|---|---|---|---|
| A | **30 组离线确定性测试**（`OFFLINE_SUITES`） | 否 | 手册不变量、端到端链路、结构体布局、命令解析、审计解析、注册表守卫、网络策略、缓解、上限、接线治理、审批对齐… |
| B | **4 个沙箱套件**（`SANDBOX_SUITES`） | 是 | `diag-bindings`、`file-cow-dispositions`、`registry-unstaged-wow64`、`delete-capture` |
| C | `sandbox-audit` | 是 | 沙箱内真实攻击探针（结构化 JSON） |

> 清单口径**以代码为准**：`src/testrunner.ts` 的 `OFFLINE_SUITES` 是唯一权威；`verify.cmd` 的循环列表必须**逐字同序同名**（`tests/suite-wiring.ts` 机器检查，此前两张清单曾静默漂移）。

### 2.2 入口命令

| 入口 | 用途 |
|---|---|
| `.\autotest.cmd` | **一键跑全部**（A+B+C）+ 写 `.t/test-report.json`；`--skip-audit` 只跑离线 |
| `.\verify.cmd` | 30 套件离线轻量关口（无报告） |
| `.\diag.cmd` | 绑定表契约 + 完整 `init()`（需未受限会话） |
| `.\run.cmd` | 手动调 CLI（`init/exec/status/review/diff/apply/audit`） |
| `.\testservice.cmd` | 常驻服务（HTTP，请求即跑测试） |

**退出码**：`0` 成功｜`1` 有失败｜`2` 环境错误。**三种总判定**：`PASS` / `PASS-OFFLINE-ONLY`（C 段因本会话受限跳过）/ `FAIL`。

### 2.3 在 Linux 沙箱里怎么跑（本次重构用到的）

Windows 专属套件在 Linux 上会因 `SANDBOX_UNAVAILABLE: requires win32` 或 `C:\` 路径而失败；**离线套件可跑**，命令：

```bash
# 单个套件
node --import tsx tests/<suite>.ts

# 类型检查（全量）
node /root/.config/opencode/node_modules/typescript/lib/tsc.js --noEmit -p tsconfig.json
```

**判据是"基线对比"而非"全绿"**：迁移前后同一套件的**通过数不得下降**。哪些失败是环境性，需逐条核（见 §四）。

### 2.4 改了代码后必须做的闸门

1. `tsc --noEmit`（全量）→ 0 错误；
2. 跑受影响的离线套件（尤其 `suite-wiring` / `baseline-integrity` / `policy-never-consistency`）；
3. **重封源码基线**（改了封印面文件后必须）：
   ```bash
   node --import tsx tools/baseline-sha256.ts --write   # 有意识刷新
   node --import tsx tools/baseline-sha256.ts --check   # 复验
   ```
   封印面（`INCLUDED_GLOBS`）：`src/*.ts`、`tests/*.ts`、`dsh-plugin/*.ts`、`plugin/*.ts`、`dsh-plugin/*.yml`、`tools/*.ts` + 根 `autotest.ts`、`verify.cmd`、`run.cmd`、`testservice.cmd`。
   > **深度 1** 限制：`plugin/policy/*.ts` 这类子目录**不在**封印面（已知残余）。
4. 新增套件要**同时**登记进 `src/testrunner.ts` 与 `verify.cmd`（否则 `suite-wiring` 红）。

## 三、修改（重构）流程

### 3.1 通用原则

1. **先取证再改动**：改前跑相关套件拿到"改前读数"，改后同口径复跑做**差值**判定。
2. **单一变更**：一次只动一件事（规范化 / 重命名 / 语义变更分开提交），出问题可二分。
3. **能不碰封印面就不碰**；必须碰时，重封基线的 **diff 就是"改了什么"的可复核记录**。
4. **未提供的保证要点名**，不要用"看起来没问题"代替证据。
5. **不写第二份实现**；重复处必须加逐字等价断言。

### 3.2 本次"全量 TS 化"的可复用配方

```bash
# 1) 从 HEAD 机械转换 .mjs→.ts 并加过渡脚手架（脚本在 .t/，gitignored）
node .t/regen-ts.mjs "$PWD"

# 2) 同步路径引用（.mjs→.ts；覆盖 dir/name.mjs 与裸 name.mjs）
node .t/sync-ext.mjs "$PWD"

# 3) 手工同步"路径之外的 .mjs 逻辑"：verify.cmd 清单、封印 glob、治理套件断言
# 4) tsc → 0；重封基线 → check 绿
```

要点：
- **只改相对说明符**（`./`、`../`），**不动**包说明符（`@deepseek-ai/...`）与 `node:` 内建；
- 迁移**连带**要同步的"非导入引用"清单：`verify.cmd` 的 `tests\*.mjs` 列表、`tools/baseline-sha256.ts` 的 `INCLUDED_GLOBS`、`tests/suite-wiring.ts` 与 `policy-never-consistency.ts` 里的 `.mjs` 断言、以及测试里 `readFileSync('src/x.mjs')` 这类字符串；
- 运行期从 `.mjs` 换成 `.ts` 后，**入口/清单/文档**里的路径都要跟着换。

### 3.3 本沙箱的**文件写入约束**（踩坑记录，`[实测]`）

| 操作 | 是否持久 | 说明 |
|---|---|---|
| 新建文件 | ✅ | |
| 删除文件 | ✅ | |
| `edit_file` 修改已有文件 | ✅ | **首选** |
| `run_command` 就地改已有文件（sed/`>`/`>>`/node 写） | ❌ | 下一次读会**回滚** |
| `run_command` 删+建（rm 后 writeFile） | ✅ | 用于批量重建 |
| `git add` / `git commit` | ❌ | **`.git` 不可提交**（index/refs 属受保护"检查点"） |

**结论**：改代码用 `edit_file`；批量重建用"删+建"；**提交必须由宿主做**（`git add -A && git commit`）。

## 四、环境约束（Windows 实测相关）

| 约束 | 现象 | 对策 |
|---|---|---|
| 无 DSH harness | `@deepseek-ai/*` 悬空到不存在的 `/root/deepseek-harness` | 在线验证留到 Windows；本机用 npm 装公开 `@deepseek-ai/*` 供 tsc |
| docker 门面 | `run_command` 被固定导向不存在的 `/run/neoai-docker/docker.sock`；`/usr/bin/docker` 是 podman 包装，rootless podman 建不了 userns（`uid_map` EPERM） | **docker 编排由宿主执行**（宿主 `docker ps` 正常） |
| 网络策略 | `download.deepseek.com`、`nodejs.org` 被拦（403） | 安装包/工具链由宿主下载；npm 走 `registry.npmjs.org` 可用 |
| KVM/TUN 不可见 | 沙箱内无 `/dev/kvm`、`/dev/net/tun` | 由**宿主 daemon** 注入 `devices:`；宿主缺则 dockurr 退 TCG |
| 平台套件 Windows 专属 | `SANDBOX_UNAVAILABLE: requires win32`、`C:\` 路径失败 | 标环境性；真实回归在 Windows 上取 |

### 4.1 Windows 实测五条判据（`docs/round16/00-测试协议.md`）

1. **loader 无告警**：`stderr.txt` 0 字节；
2. **暂存面在工作**：暂存根含沙箱写出的文件 + `candidates\*.json`；
3. **真实工作区零污染**：真实工作区只有预放种子；
4. **lane 真是 TS**：`sandbox-lane.json` 的 `degraded===false` 且 `tierEffective==='TS'`；
5. **隔离只由宿主侧读数判**：沙箱内 `Test-Path` 不得自证，须由沙箱外不受限进程对真实盘/注册表取前后读数。

> 判据 4、5 是**致命判据**：前三条全绿也可能已静默降级（R10/R16 实测）。
