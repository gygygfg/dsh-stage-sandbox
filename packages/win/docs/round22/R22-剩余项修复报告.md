## 3. 残余（R22 如实登记）

1. **注册表 R22-A 语义残余**：`RegConnectRegistryEx`（远端）/`RegOverridePredefKey`/`RegSetKeySecurity`
   是 **fail-closed + WAL**，不提供暂存/审批语义（安全方向）；`RegOpenUserClassesRoot`/`RegOpenCurrentUser`
   只读打开透传（句柄后续写入仍由其他 hook/ntdll deny 管）。
2. **枚举 R22-B 残余**：更多 `FileInformationClass` 因无安全布局不覆盖（未知类不改写 + 日志）；
   `SL_INDEX_SPECIFIED` 等不可安全重放的 QueryFlags 透传；异步完成的查询不改写（与 classic 同口径）。
3. **版本握手残余**：`judgeInjectorInit` 只覆盖"注入器报告"三态；三件套（DLL/injector/probe）仍要求
   **同版发布**（`shimInitRc` 让不同版可被发现并 fail-closed，但不自动修复/自动配对）。
4. 继承 R20/R21 的结构性残余（raw syscall、未 hook 面、T1/T0 无 WAL、>MAX_PATH 写面、跨进程 apply 无锁、
   readPolicy/mask 生产接线、R13/R14 等）不变；另有 R21 收尾复核新增的下一批候选：
   **R21-LC-01（P1，R23 已修）** `/winstage-panel/*` 曾不受 DSH BrowserAuth 围栏；R23 已接宿主 `connection.authorizeIndex`（裸请求 401 / 带 cookie 正常 / 关态 503 不泄快照）、
   **R21-LC-04（P2，R25 已提供清理工具）** remove 后 `node_modules` junction 残留、**R21-LC-05（P2）** 二次 remove 退出码非幂等。
