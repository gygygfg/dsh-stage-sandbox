# 插件启动：环境监测（fail-closed）与"关闭沙箱"的保证

日期：2026-10-08

## 1. 环境监测：不通过 ⇒ 插件拒绝启动

动机：历史行为是启动探测**只 warn**（`probeRuntime().ready === false` 也照样把插件装起来），
于是"非 Windows / 无法建立受限令牌 / ACL 后端不可用"的机器上，插件仍会接管 `ctx.fs`/`ctx.shell`，
用户见到的是一堆难懂的失败，而不是"本插件不适用于此环境"。

现在（`dsh-plugin/host-plugin.mjs` 的 `apply()`，**在所有注册之前**）：

- 开关**开**且未显式跳过时，跑一次 `probeRuntime()`，交给纯函数
  `dsh-plugin/environment-gate.mjs` 判定；**任何一项目不通过就 `throw`**
  （`code = WINSTAGE_ENV_UNSUPPORTED`）⇒ loader 行不激活、一个命令面/路由/轮询都没装起来。
- 检查项：
  1. `platform === 'win32'`（沙箱依赖 Windows 受限令牌 / ACL / Job Object）；
  2. 运行期探测 `ready`（ACL 后端可加载 **且** 本会话能建立受限令牌）。
- **逃生口必须显式写出**，默认一律判红：
  - 设置里 `probeOnStart: false`；
  - 环境变量 `WINSTAGE_SKIP_ENV_GATE=1`（开发/离线自测）。
- 探测只跑一次：门用的结果被后面的信息级日志复用。
- 离线守门：`tests/environment-gate.mjs`（7 断言），已登记进 `OFFLINE_SUITES` 与 `verify.cmd`。

> 取舍（如实声明）：这台是"全有或全无"。若你只想要暂存文件面、不需要沙箱内跑命令，而本机又建不了
> 受限令牌，请显式设 `probeOnStart:false` 或 `WINSTAGE_SKIP_ENV_GATE=1`（并接受"命令面可能不可用"）。

## 2. "设置里关闭沙箱"时的保证：原来的 shell 与文件工具保持不变

- **文件面（运行期现读开关，立即生效）**：`winstage-fs` 行始终替换 `ctx.fs` 的提供方，但每个覆盖层
  （`writeText`/`editText`/`stat`/`readText`/`watch` …）**先查 `stagingEnabled()`**；为假就直接
  `super.*` ⇒ 整体退回**平台自带的 `@deepseek-ai/dsh-fs-sandbox` 的 `SandboxedFileSystem`**
  （围栏 / `FS_SANDBOX_DENIED` / 同回合升权提示 / `sandboxMode` 广告全一致）。见
  `dsh-plugin/fs-entry.mjs`、`dsh-plugin/staging-fs.mjs`。
- **命令面（装配期判定）**：`cordis.patch.yml` 里 `pwsh-sandbox` 与 `winstage-shell` 两行的
  `disabled` 表达式**成对取反**、且**以 profile 开关为唯一权威** ⇒ 开关关时平台 `pwsh-sandbox`
  接管（完全恢复原生 shell 行为）。判定逻辑由 `tests/assembly-toggle-selftest.ts` 机器检查
  （env 三态 × profile 三态 × `ctx.baseUrl` 来源矩阵）。
  **R17 修复（P0）**：profile 覆盖层的定位不再只靠 `process.env.DSH_HOME/DSH_PROFILE`
  （实测**宿主进程没有这两个 env**；它们是 Harness 给工具子进程注入的）。现为
  **`ctx.baseUrl` 优先**（app-boot `boot()` 设为 `<profile.dir>/cordis.yml` 的目录 URL，desktop 上
  逐字为 `file:///…/.dsh/profiles/desktop/`）→ env 回退 → 都解析不出才 fail-safe 接管。
  `assembly-toggle.ts::PROFILE_SWITCH_READER_SOURCE` 与 YAML 两条表达式**逐字共享**。
- **命令/面板/轮询（运行期现读开关）**：`host-plugin.ts` 的 `isEnabled` 每次现读 loader 行表
  （`ctx.fiber.entry.parent.data` 里 `winstage-sandbox` 行的 `config.enabled`，与 fs 面同一真值）；
  设置页热写后 `/winstage*` 立即按新开关放行/拒绝、面板路由即时 503 disabled。
  **R18 修复（KNOWN-08a）**：基线漂移只读轮询改由**现读开关**启停 —— 开=正常轮询；
  关=`clearInterval` 停轮询（零 IO，不再枚举会话/读盘）+ 同节拍的轻量恢复检查（只做一次布尔判定）；
  重新打开后自动恢复轮询（**不需要重启**）。`stop()`/`ctx.effect` disposer 会把两个定时器一起清掉。
  断言：`tests/assembly-toggle-selftest.ts` §I（假定时器：启停次数、关态零 tick、恢复、dispose 对称）。
- **已知限制（如实）**：行级 `disabled` 只在**加载期**求值一次，`ctx.shell` 又是单例服务
  （两个提供方不能共存、热切换会崩宿主）⇒ **运行中**把开关关掉，**shell 提供方**要重启宿主后才交还
  平台 shell；文件面/命令面/面板/轮询则立即生效。这条差异是既定设计，不是缺陷。
- 关闭态下插件**不认领**任何共享暂存（`claimShared: isEnabled()`），也不会代别的会话去批准。

### 2.1 R19 补测出来的三条「关态零影响」保证（每条都有独立回归）

R19 之前，关闭态（`enabled:false`）仍有三处**装配期/路由期**的隐性副作用，现已修复并把判据固化进套件：

1. **关态零探测**：启动能力探测（`probeRuntime()`）此前只判 `config.probeOnStart`，不判开关 ⇒
   关态 + 默认 `probeOnStart:true` 时宿主每次启动仍会探测。它不是纯查询：会加载 ACL/win32 模块、
   在 `dirname(tmpdir())` 下 mkdir/write/rm、尝试写 `C:\Windows\dsh-probe-write.txt`、
   派生 `ping/node` 子进程验 Job Object（`src/capability.ts` 的 `probeWin32Abi`）。
   现在 `host-plugin.ts` 的启动探测在 `probeOnStart` 之后先判 `!isEnabled()` ⇒ **关态一步不跑**，
   并显式记一条「跳过启动能力探测（关态零 IO）」。回归：`tests/assembly-toggle-selftest.ts` **§J**。
2. **关态面板路由 503 且零读盘**：`buildPanelPayload()` 此前在 `isEnabled()===false` 时仍
   `readPublishedSnapshot()`，只要那份**开态时发布的**快照写着 `staging.effective:true` 就把路由
   翻成 **200 + 上一版待审**（且 GUI 每 1.5s 轮询都读一次盘）。R18 又把关态轮询改成零 IO（不再重发布）
   ⇒ 这份陈旧快照会长期存在，表现为「关掉了却仍在审批」，而 approve 此刻必拒。现在关态直接返回
   **503 `{code:'disabled'}`**（保留两张脸信息，但不读快照）。回归：`tests/crosscheck-boundaries.ts` **§6**。
3. **关态 fs 提供方不建暂存根（懒构造）**：`StagingFileSystem` 构造函数此前无条件
   `this.stagingFor(undefined)` ⇒ 经 `ReviewService → Workspace.init → Store.ensureLayout`
   在 `%LOCALAPPDATA%\Temp\winstage-stage\<键>\` **创建整套暂存根**
   （`manifest.json + staged/ candidates/ blobs/ real/ cache/ private/ staged-ext/`），
   即使开关是关的。现在删除该 eager 调用、改为**首次真正走暂存路径**才构造；
   账本落点 `unstagedLedgerDir` 改为惰性 getter（`noteUnstaged()` 只在 `stagingEnabled()` 为真的
   分支被调用，关态零触碰）。**开态**用一行 prewarm（`if (this.stagingEnabled()) this.stagingFor(undefined)`）
   保留「开态启动即建共享服务 / 迁移旧 `.dshstage/`」的既有语义；**关态绝不触发**。
   回归：`tests/crosscheck-boundaries.ts` **§7**。

> 说明：这三条修复的**源码**要经 `tools/build-plugin.ts` 重建 `dist/` 后才进入宿主运行产物；
> 回归套件直接 import 源码，因此不依赖 dist。

## 3. 审计保持"全量"

AI 进程树的文件/注册表读写审计（Method A）是**会话累计全量**：执行器初始化时设一次
`WINSTAGE_AUDIT_LOG`，所有命令追加到同一个 JSONL，每次聚合的是"截至当前"。**这是 owner 决策，
不做逐命令增量。** 详见 `docs/沙箱审计-两种记录方式实测对比.md` §5。
