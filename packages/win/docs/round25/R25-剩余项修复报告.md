## 1. R25-A（carrier）T1 真归因：opt-in T1S 档

### 设计（additive，不改默认语义）
- `WINSTAGE_T1_SHIM=1` + `--tier T1`（或等价请求 T1）且 shim 三件套可用、受限令牌可构造时 ⇒ **T1S**：
  在 T1 的受限令牌兜底之上**再挂 IAT shim**（暂存 + WAL + mask + audit），内核层仍是第二道防线。
- 解析纯函数：`resolveT1ShimOptIn` / `planT1ShimMode`（`unset`/`0`=off、`1`=on、`other non-empty`=invalid；
  非 T1 档忽略）。**显式 opt-in 但装配失败 ⇒ `T1S_UNAVAILABLE` fail-closed（不静默降回 T1）**。
- 装配：T1 的 `AclSandbox.init()` + `ensureStageGrant()`，并把 shim 运行目录（`WINSTAGE_REGSTAGE_SESSION_DIR`
  + audit 目录）**并入同一次授权的 writableDirs**；随后做**受限身份实测写** + TS 同源 shim 环境组装
  （writeShimConfig/exportMaskJson/AUDIT/REGSTAGE）+ T1S 语义探针，全部通过才切 `tierEffective='T1S'`。
- 启动：`launchT1S()` 用 **受限 launcher 启动 `winstage-inject.exe`**（注入器自身受限）⇒ 目标继承受限令牌；
  注入后 `judgeInjectorInit` 三件套握手，失败 ⇒ `T1S_INJECTION_FAILED` fail-closed。
- 报告面：`launchMode='shim+restricted-token'`、`backend='winstage-shim-iat+windows-acl-restricted-token'`、
  `enforcement='shim-user-mode+acl-restricted-token'`、`initReport.t1Shim` / `t1ShimLauncher`、
  `registryAttributionFor(T1S)=attributable:true`、T1→T1S 不记档位漂移。

### Spike（先证可行，不改 shim C）
- 方案 A（受限令牌起注入器，目标继承令牌 + 注入）**可行**：`whoami /groups` 实测目标
  `Mandatory Label\Low Mandatory Level`（`S-1-16-4096`）；`shimInitRc:0`；cmd 写区外进暂存、真盘零写。
- Spike 抓到装配必需项：**只授 stagingRoot 时 shim 报 `DshRegStageAttach failed: 3` ⇒ registry WAL 为空、归因不成立**；
  T1S 必须把 registry session dir + audit 目录一起授权并做受限身份实测写（已实现）。

### 读数
- **红（默认 T1）**：注册表写被拒（UnauthorizedAccessException）、真 hive 不变、journal 不存在/0 记录、`attributable=false`。
- **绿（opt-in T1S）**：T1→T1S；5 项判据全 pass（stagingWrite verdict=pass）；cmd/node 写区外 ⇒ 暂存、真盘零写；
  PowerShell 写 HKCU ⇒ 应用侧成功、真实 hive 不变、`session\registry\overlay.journal` **2 条**（create-key + set-value）、
  audit `reg.set`；`shimInitRc:0`。
- **fail-closed 两形态**：shim 不可用 / 非法值 `yes` ⇒ `T1S_UNAVAILABLE`，均 `silentlyFellBack=false`。
- **回退面**：默认 T1 lane 不变（`tierEffective=T1`、`attributable=false`）；TS lane smoke 正常；`executor-stub` 全绿。
- 新套件 `tests/r25-t1s.ts`：**48 断言 / 0 失败**（离线纯函数 + 源码静态守卫，无真实令牌依赖）。

### 残余（如实）
raw syscall / 未 hook 面在 T1S 下仍不可归因；T1S 不限制读取（读取面与 T1/TS 同口径）；read-only 模式的 T1S 拒绝装配
（显式 fail-closed）；依赖 canonical 三件套（`judgeInjectorInit` 拦版本不匹配）。

## 2. R25-B（lifecycle）`dsh plugin remove` 残留清理工具（R21-LC-04）

- 新工具 `tools/plugin-remove-cleanup.ts`：默认 `--dry-run`，`--apply` 才删；`--profile`/`--home`/`--json`/`--help`。
  - 候选仅限 `node_modules/dsh-winstage-sandbox` 与可证明属于它的 `.pnpm` 链接条目；
  - 只删 reparse point/链接本身（`unlinkSync`，junction 失败退回 `rmdirSync`），不递归、不跟随、不 realpath 候选，删后 `lstat` 复核；
  - 护栏：`dependencies` / `dsh.profile.bundles` / profile 或 home 覆盖层含 `winstage-*` 行 ⇒ **exit 2 + 零删除**
    （正确顺序是先 `dsh plugin remove`）；
  - 越界防护：词法严格在 `node_modules` 内 + 父目录 realpath 仍在内；实体目录/文件一律 `not-a-link` 拒删；
  - 幂等：无残留 ⇒ exit 0 + `nothing-to-do`；失败 exit 1 + 逐条明细。
- 新套件 `tests/r25-remove-cleanup.ts`：**65 断言 / 0 失败**（A–J 10 组：dry-run/apply/幂等/护栏/越界/实体目录拒绝等）。
- 隔离 DSH_HOME e2e（真实 pnpm/宿主 CLI，未碰真实 `~/.dsh`）：
  `dsh plugin add`(0) → 工具 `--apply` **exit 2 护栏拒绝**（零删除）→ `dsh plugin remove`(0，**junction 残留复现**) →
  `--dry-run`(0，不删) → `--apply`(0，removed=1，**packages/win 内容逐字节不变**) → 二次 `--apply`(0，`nothing-to-do`) →
  重启路由 **404**。gate-runner 独立驱动 **23/23** 绿。
- 残余：**R21-LC-05（二次 `dsh plugin remove` exit 1 / `ERR_PNPM_CANNOT_REMOVE_MISSING_DEPS`）仍是宿主 CLI 面，不修**；
  本工具与它正交（插件已卸载后才清理）。

### 最终轮抓到的两个问题（均已当场修复并复跑绿）

1. **R25-D（产品缺陷，file-shim）**：R24-B 回滚在跨进程并发下出现 lost-update——`r21-file B4.1` 采样出现
   w1 `applied` + w2 `rolled-back` ⇒ 真实内容被打回 base（w2 回滚覆盖 w1 成功写入）；根因是回滚把**首个失败条目**
   （本进程没写过）也纳入恢复、且只按本进程快照判断。修复：① `<store.dir>/apply.lock` **跨进程 apply 锁**
   （O_EXCL；等锁 30s 后重读候选 ⇒ 已 applied = `ALREADY_APPLIED`；超时 `APPLY_LOCK_TIMEOUT`；崩溃遗留锁
   mtime>120s 清除）；② **回滚只恢复 `applied[]`（本进程确实写过的路径）**，失败条目不再回滚。
   复跑：`r21-file` 24/0（多采样稳定，real=CONC-NEW）、`r24-atomic-apply` 13/0；gate-runner 独立多采样绿。
2. **r24-fs-config 套件不自包含（测试缺陷，fs-policy）**：A1 子进程脚本写死未跟踪的 `.t/fs-policy/...`，

   自生成 + 新增"夹具自生成"前置断言（断言数 68→**69**）。清 `.t/fs-policy` 后 **69/0**，gate-runner 独立复跑一致。
