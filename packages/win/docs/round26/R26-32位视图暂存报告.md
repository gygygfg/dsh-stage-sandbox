## 2. 修复模型（reg-shim）

- **暂存表示**：overlay app hive 无视图概念 ⇒ 32 视图键写成合成命名空间 `HKCU\__DSH_WOW64_32__\...`
  （短 hive 名后的专用段；真实键名不可能与整段冲突）。WAL 记录 `reserved` 字段携带视图
  （`0`=默认/64，`1`=WOW64-32；旧日志 `0` 兼容），`ws_t3reg.c` 校验 `0/1`。
- **句柄继承**：`RegOpenKeyExW`/`RegCreateKeyExW` 带 `KEY_WOW64_32KEY` 的**写意图** open 登记 handle→view 表；
  后续 `RegSetValueExW`/`RegDeleteValueW` 落同一前缀。读类 open 一律透传（不投影 overlay）。
- **apply**：候选/覆盖层把变更拆 `(真实路径, view)`；`src/registry-bindings.ts` 的 `reg.exe` 后端在 `view=1` 时补
  `/reg:32`；`dsh-plugin/registry-capture.ts` 与 `src/registry-stage.ts` 同步（`displayPath`/`registryView`）。
- **审阅面**：`review-service` 的 registry 行 `path: change.displayPath ?? change.path`（`[32] HKCU\...`），
  并附 `registryView` —— 不把 32 视图显示成 64 路径而误导审批。
- **护栏**：64 视图命中合成段 ⇒ fail-closed（原因码 5，防御性）；WOW64 进程内视图位仍 fail-closed（1/2）；
  raw syscall / 未 hook 面不变。改动文件：`shim/src/ws_reg.c`、`ws_regstore.c`、`ws_t3reg.c`、
  `src/registry-stage.ts`、`src/registry-bindings.ts`、`dsh-plugin/registry-capture/`+`review-service.ts`；
  **未改** `winstage_internal.h`/`ws_hook.c`。

### 最终轮抓到的 R26-GATE-01（P2，已修）

- **现象**（gate-runner `--phase post` 首轮，dll `7775A755…`）：**32 视图真实键已存在**时，
  `reg add <KEY> /v X /f /reg:32` 的写意图 open 走 passthrough ⇒ WAL 记真实路径 `HKU\<SID>_Classes\WOW6432Node\...`、
  `reserved=0`、候选 `registryView=DEFAULT`、`displayPath` 无 `[32]`；apply 物理上仍落 32 视图，但**归因/审阅面错误**
  （违反"WAL 带视图、审阅面不能误导审批"）。对照：键**不存在**时 WAL 正确 `view=1`。
- **根因（两叠加）**：① `ws_reg_path_strip_view` 把相对路径（`__DSH_WOW64_32__\...`）误当规范路径剥掉首段 ⇒ real probe
  走 64 视图；② 32 视图 create/open 返回真实句柄，视图只靠 handle→view 表，reg.exe 关闭/重开后丢失。
- **修复**（reg-shim）：`ws_reg_path_has_view` 支持相对形式、`strip_view` 用"首段是否短 hive 名"区分规范/相对；
  `RegCreateKeyExW(32KEY)` 真实键已存在时不再回真实句柄（materialize + pseudo handle，`REG_OPENED_EXISTING_KEY`）；
  `RegOpenKeyExW` 写意图 + 32 视图一律返回带合成段的 pseudo handle（读类仍透传）。
- **复验**：`r26-wow64-registry` 扩到 **41 断言**（新增已存在键 add/delete/apply 用例）41/0；gate-runner 同驱动
  post **24/24**（D1/D3/D4 view=1 + `[32]`，apply 仅 32 视图、64 不变）。

## 5. 残余（R26）

1. **读不投影**：`reg query /reg:32` 只看真实 32 值，不回读 overlay 中已暂存的 32 视图内容（staging 是"写后审"模型；
   与 64 视图同口径）。
2. **WOW64 进程内视图位仍 fail-closed**（x64 shim 不注入 WOW64 进程，保留防御）。
3. **HKCU 仅部分区域重定向**（验收键必须用 CLSID/Interface 等重定向区；HKLM 视图写需管理员，本机 Medium 不可用）；
   超长路径 + 32 视图、WOW64 进程注入未覆盖（合同排除项）。
4. raw syscall/未 hook 面不变；其它继承 R20–R25 残余。
