## 1. R23-A（Lead）R21-LC-01：`/winstage-panel/*` 本机鉴权缺口 —— 已修

- **修前红（gate-runner 隔离实例，端口 64366，干净进程 curl）**：裸 `GET /` = 401（BrowserAuth 对 index 生效），
  但裸 `GET /winstage-panel/snapshot?session=` = **200 OK + 全量 JSON（snapshot/workspaceRoot/staging/redactions）**、
  `GET /winstage-panel/trust?session=` = 200 ⇒ 本机任意进程无需 token/cookie 可读审阅快照。
  根因：面板是**命名前缀路由**，`dsh-host-webserver` 的命名路由先于前端静态兜底，
  宿主 BrowserAuth（`Connection.authorizeIndex`）只在兜底里调用（`dsh-host-frontend-static/lib/index.js:95`）。
- **修复**（`dsh-plugin/host-plugin.ts`）：
  - `createPanelHandler({ authorize })`：在 `buildPanelPayload()` **之前**调用授权钩子；返回 false = 授权方已写
    401/403 响应、直接返回；抛错 = fail-closed 503 `{code:'auth-unavailable'}` 且不构建 payload（未授权零读盘）；
    未传 `authorize` = 兼容旧行为（离线单测显式选择；生产由静态守卫强制传）。
  - `apply()`：`ctx.inject(['webServer','connection'])`；把
    `authorize: (req,res) => connection.authorizeIndex(req,res, secureListener)`（`secureListener =
    webServer.protocol==='https:'`，与 `dsh-host-frontend-static` 同口径）交给 handler；
    **connection 服务缺失 ⇒ fail-closed 不注册无鉴权路由**（error/warn 日志），绝不退化为旧缺口。
- **修后绿（gate-runner 独立复核，隔离实例开态 57633 / 关态 58688，干净进程 curl，14/14 全绿）**：

| 场景 | 读数 |
|---|---|
| 开态裸 `/` | 401（不变） |
| 开态裸 `panel/snapshot`、`panel/trust`、bogus session | **401**（body 只有 `dsh web authentication required; …`，**无 snapshot**）；401 不带 Set-Cookie |
| `GET /?token=…` | 303 + `Set-Cookie dsh-auth-…` |
| 带 cookie `/` / `panel snapshot` / `panel trust` | 200 / **200 + snapshot** / 200（allow 路径未打断） |
| 关态裸 `/` / panel | **401 / 401**（鉴权先于开关，不制造 enable/disable 预言机） |
| 关态带 cookie panel snapshot | **503 `{code:"disabled"}`，body 无 snapshot/files**（R19 D2 语义保持） |

- 回归：新增 `tests/r23-panel-auth.ts`（**18 断言**，`--plant` 2 红自证）；`crosscheck-boundaries` 41/0、
  `assembly-toggle-selftest` 104/0、`policy-never-consistency` 26/0。
- 残余：`authorizeIndex` 校验的是宿主签名的 `dsh-auth-*` cookie（进程 secret）；插件不持有/不复制该 secret，
  只调用宿主服务 ⇒ 无新增密钥面。非 Web 装配无 `webServer` 时面板路由本来就不注册；有 `webServer` 无 `connection`
  的装配现在 fail-closed 不注册（面板不可用，但不会静默暴露快照）。

## 2. R23-B（file-shim）R21-FS-06 收窄：>MAX_PATH 写/建目录/rename/delete —— 已修

- **修前红**（canonical R22 `AC7C687D…`，native 探针 Medium IL，`\\?\` >MAX_PATH）：
  `CreateFileW` 写 / `CreateDirectoryW` / `MoveFileExW` rename / `DeleteFileW` 全部 `RC=0 ERR=5`（fail-closed），
  真盘零写/零删；`CreateFileW` 读（R21-FS-09）透传正常。短路径四操作对照进暂存。
- **修复**（provider 侧长路径安全处理 + shim 真实 API 边界）：
  - `ws_util.c`：`ws_path_api_w()`（真实 API 边界 ≥240 字自动补 `\\?\`/`\\?\UNC\`）、`ws_open_file_raw_flags`/`ws_ensure_dirs`；

  - `ws_mask.c`：长路径 mask 加固——≥240 字输入要求`归一化 leaf`与`输入 leaf`一致，否则 **fail-closed**

    A13 长 stage 根 + 短路径。**私有 13/0/0；canonical 13/10（先红后绿自证）**。

   —— 面板不可用属可接受失败方向，已记录。
2. R23-B 的残余以 file-shim findings 为准（更多 API/UNC/长路径 rename 语义）。
3. 继承 R20/R21/R22 的其余残余（raw syscall、未 hook 面、T1/T0 无 WAL、R13/R14、生产 readPolicy/mask 接线、
   `dsh plugin remove` 清理、autotest/ebk 长跑等）不变。
