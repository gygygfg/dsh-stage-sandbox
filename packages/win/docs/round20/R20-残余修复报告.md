## 0. 一句话结论

R19 §3 登记的 **5 条残余（R16–R20）全部收口**，其中 4 条真正修掉、1 条（R20②）按合同收窄为
**机读的结构化"不可归因"声明**（不声称已归因）：

- **R16**：ntdll/Zw 注册表写直调 24 个入口全部 fail-closed + WAL（真实 HKCU 一字节不动）；
  并修掉修复过程中暴露的 **自打死 re-entrancy P0**（shim 自己的 staging 引擎被自己的 deny 打死）。
- **R17**：`ReplaceFileW/A`、`NtCreateFile`、`FindFirstFileW/A/ExW/ExA`、`FindNextFileW/A`、`FindClose`、
  `NtQueryDirectoryFile` 全部接线；`CopyFileEx/2` 暂存语义载体矩阵补齐并给出明确结论。
- **R18**：硬链接遮蔽**读面 + 建链面双收口**（枚举全部链接名精确判定，不误伤 pnpm/WinSxS）。
- **R19**：目录枚举过滤覆盖 **cmd / PowerShell / node / 原生 FindFirstFileW** 四载体。
- **R20①**：纯托管 .NET exe 注入崩溃根因（AnyCPU PE32 被按 x64 thunk 解析）+ 延迟初始化，托管 exe
  直启、写/删/注册表全部进暂存且真实盘零写；**R20②**：T1/T0 的"被拒写不可归因"变为
  `initReport.sandboxInit.registryAttribution` 机读字段。
- **额外（核对 R17 验收面时实测新发现，P0）**：NT 命名空间/设备别名路径旁路
  （`\Device\HarddiskVolumeN`、`\??\Volume{GUID}`、`GLOBALROOT`、`\\.\X:`、`SystemRoot`）在
  `ws_NtCreateFile` 解析失败分支被一律透传 ⇒ 写/读/删真实盘。已按方案 A 映射为 Win32 路径接入
  同一暂存/遮蔽/whiteout 管线，映射不了的一律 fail-closed（详见 §3.3b）。

最终：canonical shim 与 dist 由 Lead 从冻结源码统一重建；`tsc=0`；源码基线重封 **149 条**；
`verify.cmd` **38 套件**（原 35 + 3 个 R20 新套件）全绿；R20 新增/扩展套件与 gate-runner 独立矩阵
修前红 → 修后绿。**不声称**"TS 档已是硬边界"：raw `syscall`、未 hook 面、T1/T0 无 WAL 仍是结构性残余。

## 4. 残余（收窄后的如实声明）

R16–R20 的原文行已在 `docs/Windows功能开启清单.md` §13 改写为"已收口/收窄"，**残余本身仍在**：

1. **RAW `syscall`**（R16/R17/R18 共同）：不经过任何 IAT 槽，任何 IAT 钩子与 ACL 之外的机制都拦不住；
   TS 档的结构性上限，只有 T1 令牌/T0/AppContainer 能兜底。
2. **未 hook 面**：`NtQueryDirectoryFileEx`（目录枚举 Ex 变体）、`NtOpenKey/ZwOpenKey`（纯打开）、
   `NtWriteFile` 直写（拿到含写权限的 handle 后）。守卫：`tests/r20-file-boundaries.ts` A4、
   `src/registry-stage.ts::REG_STAGE_UNHOOKED_APIS`。
2b. **R20-FS-10 收窄（设备/NT 别名）**：可映射形态（HarddiskVolume/Mup/Volume GUID/UNC/DosDevices/
   GLOBAL??/SystemRoot/`\\.\X:`/GLOBALROOT）已收口；映射不了的（PhysicalDriveN / NamedPipe / 未知
   `\Device\…` / `\Sessions\…`）在 NtCreateFile 写删与 mask 读、`NtOpenFile(delete-on-close)`、mask 生效下的
   设备句柄枚举上 fail-closed；mask 未声明时的纯读与 Win32 `CreateFileW` 对原生设备对象沿用放行。
   另有 4 条已登记小残余：盘符映射为进程内首帧快照（新挂载卷落 fail-closed）、Volume GUID 取首个挂载点、
   SystemRoot 仅系统目录、handle-relative 纯读（findings R12a–f）。
3. **R17 收窄**：`ReplaceFileW` 无暂存语义（fail-closed）；robocopy 在沙箱内不可用（fail-closed）；
   handle-relative `NtCreateFile` 写 deny/读透传；`MAXIMUM_ALLOWED` 读透传。
4. **R18 收窄**：多链接文件枚举失败时 fail-closed（极端 ACL/网络路径可能误拒）；CreateHardLink 非遮蔽源
   有源内容物化复制成本。
5. **R19 收窄**：异步完成的 `NtQueryDirectoryFile` 原样透传；FindFirst* 模式目录段含通配符时不重建路径；
   **目录枚举不与 overlay 合并**（预存模型限制，canonical/R20 同一探针读数相同，非 R20 引入）；
   stage root/passthrough 前缀内目录不过滤。
6. **R20② 结构性**：T1/T0 无 shim ⇒ 被拒写无 WAL，本改动只提供**结构化"不可归因"声明**，
   不把 `Access denied`/空 WAL 读成归因结论；raw syscall/未 hook 面同样不可归因。
7. **R20 部署残余**：三件套（DLL/injector/probe）**必须同版发布**——旧注入器 + 新 DLL 会
   "加载成功但永不初始化"；已用套件静态断言 + report `shimInitRc` 使其可被发现。
8. 既有口径（R1 读取面不收敛、R2 网络不收敛、T1/T0 无 WAL 等）R20 **未改变**，见 §13 R1–R15。

## 7. 结论与后续

- R16–R20 的五条残余都有**先红后绿**证据；其中 R20② 是**如实收窄**而不是修掉（T1/T0 无 shim 的结构性限制）。
- 最高优先级后续：① raw `syscall`/未 hook 面的**硬边界**只能靠 T0/AppContainer（读面/写面）或未来内核回调；
  ② `NtQueryDirectoryFileEx` 枚举过滤；③ `ReplaceFileW` 的暂存语义；④ 三件套版本握手前置到 executor（当前靠 report 字段）；
  ⑤ 设备/NT 别名的 4 条小残余（盘符缓存首帧、Volume GUID 首挂载点、SystemRoot 仅系统目录、handle-relative 纯读）
  与映射不了形态的 fail-closed 面；⑥ T1 lane 的 `execution.classification` 对"探针自报被拒"的 exitCode=2 误判为
  `runner-failure/可执行文件没找到`（gate-runner 观察项，文案误导，非验收面，未在本轮修）。
- **不声称**"TS 档已是硬边界"：它仍是 IAT 钩子 + 暂存的用户态边界；硬边界只能靠 T1 受限令牌或
  T0/AppContainer 兜底——这一条与全部读数一起如实记录。
