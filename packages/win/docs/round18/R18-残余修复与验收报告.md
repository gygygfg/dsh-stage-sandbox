## 3. 过程事故与教训（如实记录）

1. **canonical 产物完整性标签**：12:38 的第一次 canonical 由 **Low IL 的 agent shell** 构建 ⇒ 三个产物被打 **Low 完整性标签** ⇒ injector 启动子进程 `TS_INJECTION_FAILED`/exit 127、沙箱套件假红。12:59 起改由 **Medium IL（Task Scheduler/WMI）构建**，`build-shim` 自带 `integrity: repaired a Low mandatory label … Low->Medium` 读数，之后 lane/套件才真实。
2. **`%TEMP%` 路径伪影**：本会话的 Task Scheduler/WMI 通道里，**stage 根放 `%TEMP%`/`C:\Temp` 时连 golden 旧 DLL 的 shim 初始化都会失败**（probe `write_out` exit 3 / init 3），而 workspace 内 stage 正常；因此 lane/套件读数统一用"fake LOCALAPPDATA/TEMP 指向 workspace 内 `.t`"的口径。**生产形态（真 `%TEMP%` stage）的 lane 本会话 not-run**，需在真实宿主重启后复验（不得据此声称 R15 已解除）。
3. **干扰型红**：`baseline-integrity`/`registry-conformance A.2/A.5`/`residuals` 的部分红来自"重封前/重建后证据过期"与"测试复用确定性 store 不复位"（crosscheck-r17 独立复跑需唯一 `WINSTAGE_STAGE_ROOT`）；已逐项复跑澄清，不是产品回归。
4. **测试夹具问题**：KNOWN-07 的 c10（硬编码 Administrator）、KNOWN-06 的 c4b（撤销经 `DeleteFileW` 被 ntdll 拦截成 whiteout）、paths-masks 的 fake-appdata 探针、e2e 的 `pwsh` 不存在/相对路径等，均已修在测试/probe 层并留下红→绿对照。
