### 1.1 一个实测出来的语义差（写进 `config.ts` 注释）

真 schemastery 对 `meta.volatile === true` 的字段，**校验输出是 `Volatile` 引用对象**（`{ get(), [Symbol.for('cosmokit.volatile.write')] }`），
而非普通标量；旧手写 `schema.js` 只摆了 `meta.volatile` 却没实现包装，**产出普通值**。
⇒ `plugin/config.ts` 提供 `readConfigValue()/boolOf()/stringOf()`，并让 `plugin/index.ts` 的
`normalizeConfig()` 在委托前把两形态统一成普通值，于是"用真 schema"与"行为不变"同时成立。

`[实测]`：`Config({})` → `enabled` 为引用对象，`boolOf(...,true)` → `true`；`Config({enabled:false})` → `false`。

## 2. `cordis.patch.yml` 的 `!!js` 双份漂移 —— **已由测试守住，本轮不改写**（[实测]）

原计划"重写 `cordis.patch.yml` 消除 `!!js` 双份漂移"。核查后判定**不应改写**，依据三条：

1. **已被机器约束**：`tests/assembly-toggle-selftest.mjs` `[实测]` **26 项全绿**，其中
   A7/A8 断言两条 `disabled: !!js` 表达式**逐字共享**同一段开关读取代码（防"只改一条"）；
   B 段用 env×profile 7 组矩阵断言"**恰好一个** shell 提供方启用"+ fail-safe；
   C 段变异自证证明 B 有分辨力；A5/A6 钉住两个已知 YAML 陷阱（`!!js !` 与 `: `）。
2. **`!!js` 是 load-bearing**：行级 `disabled` 在**装载期**求值，此时拿不到合并后的 profile config，
   只能直接读 profile 文件；删除它会让 bundle 失去"fail-safe 接管"的默认，且**服务名单例**
   （两个都禁用 ⇒ shell 不可用；两个都启用 ⇒ 加载失败）必须靠这对表达式互斥。
3. **本机无法验证改写**：没有 DSH loader 可跑，YAML `!!js` 形态敏感（该文件历史上因
   `: ` 与 `!!js !` 两次把整条 bundle 静默跳过）。在不可验证处改它是**净负风险**。

**残留缺口（留待阶段 2，assembly-toggle 转 TS 时一并收口）**：YAML 内联表达式是这份逻辑的
**第三份拷贝**，现有自测只交叉校验了 YAML 的两份，**没有**断言它们与
`assembly-toggle.mjs` 的 `winStageEnabledInProfileText()` 等价。阶段 2 把该模块转 TS 后，
补一条"YAML 表达式 ≡ TS 纯函数"的等价断言即可闭合。

## 4. 阶段 2 的迁移约束（[推断]，基于 import 面）

`.mjs` ↔ `.ts` 互操作有一个硬约束：**纯 Node 运行的 `.mjs` 不能 `import` `.ts`**（无 TS loader）。
因此"叶子优先"的迁移必须满足"被迁移文件的**所有 `.mjs` 导入者**也已迁移或不需要它"。
阶段 2 需先做一次 **import 面分析**，按依赖拓扑确定转换顺序，并保留 `.mjs` 薄壳（re-export）
作为过渡边界，直到最后一个 `.mjs` 导入者消失。

> 平台引擎（`src/*.mjs`，约 1.6 万行）与 Cordis 规范**正交**：规范约束的是插件接口
> （`Config`/`inject`/`apply`/服务注册），不是内部实现语言。故"符合 Cordis 规范"的
> 关键面是**外壳**；引擎的 TS 化按价值/风险单独决策，不纳入"规范合规"的必做项。
